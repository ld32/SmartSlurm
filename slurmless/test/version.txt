How drift is controlled
-----------------------
slurmless is a component of SmartSlurm (one copy, in-tree), so the harness and the
tools it tests always share a commit and cannot drift apart. Just run the harness
before pushing a tool change (./slurmless/bootstrap.sh, then the relevant blocks)
— that is the regression net; no checksum pin is needed.

When you run the harness against an EXTERNAL SmartSlurm checkout (SMARTSLURM_ROOT
pointed at a different clone), the tools can be any version, so the checksums below
record the tree this harness was last validated against. A mismatch is not
necessarily a problem — SmartSlurm's bin/ is a moving target — it just means
re-validate and update this file.
